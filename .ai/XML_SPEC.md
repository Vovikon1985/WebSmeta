### Шаг 1: Получение файла

Пользователь должен предоставить реальный XML-файл ГРАНД-Сметы.

- Формат: `.xml`
- Кодировка: UTF-8 или Windows-1251 (определить при анализе)
- Размер: любой (даже большие сметы с сотнями тысяч позиций)
- Содержимое: реальная смета из ГРАНД-Сметы

**Конфиденциальность**:
- Если файл содержит чувствительные данные (названия компаний, точные суммы), пользователь может:

### Правила преобразования типов

| XML тип | Domain тип | Правила преобразования |
|---------|-----------|------------------------|
| Строка | `string` | Trim, проверка на null/empty |
| Число | `decimal` / `double` | Парсинг с учётом локали, проверка диапазона |
| Дата | `DateTime` | Парсинг ISO 8601 или формата ГРАНД |
| Boolean | `bool` | "true"/"false", "1"/"0", "yes"/"no" |
| Перечисление | `enum` | Маппинг строковых значений |

### Обработка отсутствующих значений

| Сценарий | Действие |
|----------|----------|
| Обязательное поле отсутствует | Ошибка импорта, логирование, возврат Result.Failure |
| Необязательное поле отсутствует | Значение по умолчанию (null, 0, empty) |
| Поле содержит пустую строку | Обработать как null или значение по умолчанию |
| Поле содержит некорректные данные | Логировать warning, использовать значение по умолчанию или пропустить позицию |

## 🔍 Правила валидации XML

### Валидация структуры

1. **XML well-formed**: Файл должен быть валидным XML
2. **Корневой элемент**: Должен соответствовать ожидаемому
3. **Namespace**: Если используется, должен совпадать
4. **Кодировка**: Должна поддерживаться

### Валидация содержимого

1. **Обязательные поля**: Все обязательные поля должны присутствовать
2. **Типы данных**: Числовые поля должны содержать числа
3. **Диапазоны**: Значения должны быть в допустимых диапазонах
4. **Идентификаторы**: Должны быть уникальными в пределах документа
5. **Связи**: Ссылки на родительские элементы должны существовать

### Обработка ошибок валидации

| Тип ошибки | Действие |
|------------|----------|
| XML не well-formed | Прервать импорт, показать ошибку с номером строки |
| Отсутствует обязательное поле | Прервать импорт или пропустить элемент (настраивается) |
| Некорректный тип данных | Логировать warning, использовать значение по умолчанию |
| Дублирование идентификатора | Логировать warning, использовать первый или последний (настраивается) |
| Некорректная ссылка | Логировать warning, пропустить элемент |

## 📦 Хранение оригинального XML

### Требования

1. **Оригинальный XML НЕ изменяется**
2. **Сохраняется как есть** в папку `Source/`
3. **Имя файла**: `Estimate_Original_{EstimateId}.xml` или `Estimate_Original_{timestamp}.xml`
4. **В SQLite хранятся только метаданные**:
   - Путь к файлу
   - SHA256 хэш
   - Размер файла
   - Дата импорта
   - Версия формата

### Структура хранения

```
Project/
├── Source/
│   └── Estimate_Original_2026-08-13.xml    # Оригинальный XML
├── Project.db                               # SQLite с метаданными
└── ...
```

### Запись в SQLite при импорте

```sql
INSERT INTO Estimate (
    Id, ProjectId, Name, SourceFilePath, SourceFileHash,
    ImportedAt, Version, TotalItemsCount, Status, CreatedAt, UpdatedAt
) VALUES (
    @id, @projectId, @name, @sourceFilePath, @sourceFileHash,
    @importedAt, @version, @totalItemsCount, 'Imported', @createdAt, @updatedAt
);
```

### Выбор технологии парсинга

| Технология | Когда использовать | Преимущества | Недостатки |
|------------|-------------------|--------------|------------|
| `XmlSerializer` | Структура известна и стабильна | Простота, автоматический маппинг | Требует точного соответствия структуры |
| `LINQ to XML` (XDocument) | Гибкий парсинг, сложные запросы | Удобный API, запросы | Загружает весь документ в память |
| `XmlReader` | Большие файлы, потоковая обработка | Минимальное потребление памяти | Более сложный код |

**Рекомендация для больших смет (50 000+ позиций)**: Использовать `XmlReader` для потоковой обработки, чтобы не загружать весь XML в память.

## 🧪 Тестирование XML Import

### Обязательные тесты

1. **Парсинг валидного XML**: Должен успешно распарсить и сохранить в SQLite
2. **Парсинг невалидного XML**: Должен вернуть понятную ошибку
3. **Парсинг пустого файла**: Должен вернуть ошибку
4. **Парсинг файла с отсутствующими обязательными полями**: Должен вернуть ошибку или warning
5. **Парсинг большого файла (10 000+ позиций)**: Должен завершиться за разумное время
6. **Парсинг файла с разной кодировкой**: Должен корректно определить кодировку
7. **Сохранение оригинала**: Оригинальный XML должен быть сохранён без изменений
8. **Хэш файла**: SHA256 хэш должен совпадать
9. **Повторный импорт того же файла**: Должен быть обнаружен дубликат
10. **Импорт с повреждённым XML**: Должен быть обработан gracefully

### Производительность

| Размер файла | Количество позиций | Максимальное время импорта |
|--------------|-------------------|---------------------------|
| Малый | < 100 | < 1 секунда |
| Средний | 100 - 1 000 | < 5 секунд |
| Большой | 1 000 - 10 000 | < 30 секунд |
| Очень большой | 10 000 - 100 000 | < 5 минут |
